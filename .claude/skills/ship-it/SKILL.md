# Ship It — Full PR Workflow

You are shipping changes through a complete PR workflow: branch, commit, push, PR, merge.

## Current repo state
- Remote: !`git remote -v | head -1`
- Current branch: !`git branch --show-current`
- Repo root: !`git rev-parse --show-toplevel`
- Working tree status: !`git status --short`

## Step 1: Gather information

Check if `$ARGUMENTS` were provided. Arguments can be:
- `<branch-name>` — e.g., `fix/character-images`
- `<branch-name> <commit-message>` — e.g., `fix/character-images "fix: swap character images"`

If arguments are missing or incomplete, use AskUserQuestion to ask:

**Question 1 — Branch type:**
What type of change is this? Options:
- **feat/** — New feature or addition
- **fix/** — Bug fix or correction
- **docs/** — Documentation only
- **style/** — Styling, formatting, CSS changes
- **chore/** — Maintenance, config, tooling

**Question 2 — Branch name:**
Short descriptive name for the branch (e.g., `character-images`, `readme-badges`). Free text — provide sensible options based on the changed files:
!`git diff --name-only HEAD 2>/dev/null | head -5`

**Question 3 — Commit message:**
One-line commit message describing the change. Free text — suggest a message based on changed files:
!`git diff --stat HEAD 2>/dev/null | tail -1`

## Step 2: Verify there are changes to ship

```bash
git status --short
git diff --stat
```

If the working tree is clean and there are no staged changes, STOP and tell the user:
> "Nothing to ship — working tree is clean. Make your changes first, then run `/ship-it` again."

## Step 3: Create the branch

Construct the full branch name from the type prefix + name (e.g., `fix/character-images`).

```bash
git checkout main
git pull origin main
git checkout -b <branch-name>
```

If the branch already exists, ask the user:

**Question: Branch `<name>` already exists. What do you want to do?**
- **Delete and recreate** — start fresh from main
- **Switch to it and continue** — use existing branch
- **Pick a different name** — enter a new name

## Step 4: Stage and commit

Show the user what will be staged:
```bash
git status --short
```

Use AskUserQuestion to confirm:

**Question: Stage all changed files, or select specific files?**
- **Stage all changes (Recommended)** — `git add -A`
- **Let me pick files** — show file list for selection

If "Let me pick files", list the changed files and ask which to include.

Stage the files:
```bash
git add <files>
```

Commit with the message. Always append the co-author line:
```bash
git commit -m "$(cat <<'EOF'
<commit-message>

Co-Authored-By: Claude Opus 4.6 <noreply@anthropic.com>
EOF
)"
```

## Step 5: Push and create PR

Push the branch:
```bash
git push -u origin <branch-name>
```

Generate a PR body from the commit. Include:
- Summary (bullet points of what changed)
- Test plan (checklist based on file types changed)
- Generated-with footer

Create the PR:
```bash
gh pr create --title "<commit-message>" --body "$(cat <<'EOF'
## Summary
<auto-generated bullet points from git diff --stat>

## Test plan
<auto-generated checklist based on changed file types>

🤖 Generated with [Claude Code](https://claude.com/claude-code)
EOF
)"
```

## Step 6: Merge

Use AskUserQuestion to confirm:

**Question: PR created. How do you want to merge?**
- **Squash and merge (Recommended)** — single clean commit on main
- **Merge commit** — keeps all commits
- **Rebase and merge** — linear history
- **Don't merge yet** — leave PR open for review

If merging:
```bash
gh pr merge --squash --delete-branch
git checkout main
git pull origin main
```

## Step 7: Summary

Print a clear summary:
```
Shipped!

Branch:  <branch-name>
PR:      #<number> — <title>
Merged:  <method>
Status:  On main, up to date

Files changed:
  <file list with +/- stats>
```

## Error handling

- If `git push` fails due to authentication, tell the user to check `gh auth status`
- If `gh pr create` fails because a PR already exists, show the existing PR and ask if they want to update it
- If merge fails due to branch protection, explain what's needed (reviews, CI checks)
- If there are merge conflicts, do NOT force — tell the user to resolve them
- If the branch already exists remotely, ask before force-pushing
